# Omniwand: Claude dev guide

Native Windows AI cursor and desktop wand for ArkStation. This file is intent and operator guidance; the code in this folder is the source of truth.

## Where things live

| Path | Purpose |
| --- | --- |
| `E:\ArkStation\augments\omniwand` | This app (.NET 10, WinForms + Win32/GDI+). |
| `E:\ArkStation\.ark` | ArkStation repo. Work in a SolaTree worktree, never the root checkout. |
| `logi-mx4-plugin\` | Logi Options+ / MX Master 4 plugin (separate project, packs to `dist\ArkStationOmniwand.lplug4`). |

## Files

- `Program.cs`: app context, tray menu, render loop, overlay window, Win32 imports, `NativeCursorManager`, Named Pipe server `ArkStation.Omniwand.Control`.
- `ArkStationClient.cs`: Model Gateway `:8788`, Input Studio `:8842`, PC-Modz `:8830`, Wiz routing, `SelectedModel`.
- `GrimXFlowOrb.cs`, `GhostTrailerEngine.cs`: 8-slot orb and voice/dictation ribbon.
- `OmniwandHudForm.cs`, `WizCraftingWidgetForm.cs`, `AInboxIntakeWidgetForm.cs`: summoned widgets.
- `PhosphorKit.cs`: the widget primitive layer (fonts from `@ark/tokens`, EyebrowLabel, DataLabel, PhosphorButton, PhosphorBadge, PhosphorField, PhosphorComboBox, PhosphorCheckBox, WidgetChrome, SpecCardPanel). Every summoned widget composes these; swap here when the component library lands. PhosphorComboBox paints its whole closed box (no system drop button) and frames its drop list in line-2 with the system dark scrollbar; PhosphorCheckBox is fully owner-drawn. Never use a raw `ComboBox` or `CheckBox`.
- `PhosphorTheme.cs`: every color, radius, spacing step and type size, resolved from `PhosphorTokens.cs` and immutable at runtime, plus `Locals`, the two values Omniwand keeps apart from the tokens on purpose (eyebrow 10px and 0.16em per rule 6, where the token says 12px and 0.12em).
- `PhosphorTokens.cs`: generated by `tools/gen_phosphor_tokens.py` from `packages/tokens/src` (colors.css, spacing.css, typography.css). Never hand-edit; rerun the script and rebuild when the tokens change.
- Fonts: `PhosphorFonts` loads every face privately from `distonts`: JetBrains Mono and Archivo Black from `packages/tokens`, plus Inter SemiBold (600, `Ui`), Inter ExtraBold (800, `Ui(heavy)`) and Space Grotesk (400, `Body`) from `assets/fonts` (Google Fonts static instances, OFL licenses beside them; not in `packages/tokens` yet). GDI+ names each static weight as its own family. Segoe UI is only the fallback when a file is missing.
- `SurfaceCapture.cs`: as-built captures. Pipe command `render:<folder>` makes the running app draw its real surfaces offscreen to PNG: the tray menu at rest and with the orb row lit, the orb submenu, one toast per tone, HUD, Wiz and AInbox. Each is clipped to its window region; hidden widgets are shown off-screen without activation for the draw. The Claude Design canvas (Omniwand UI) shows these on its As built row next to the design targets; re-run it after UI changes and re-upload.
- Wiz model: Antigravity names Argon `gemini-4-argon-medium` (`agy models`); `gemini-argon` was never a real id. Print mode is `agy --model <id> -p <prompt>` (no `chat` subcommand). The gateway fallback only sends `ark/` models and otherwise answers with `ark/kimi`, labelled as such.
- `OverlayZGuard.cs`: owns the overlay's z-order. It re-asserts HWND_TOPMOST every 250 ms (not only while moving), and when a visible window still sits above the overlay under the pointer (Start, Search, taskbar and tray flyouts live in bands no topmost window can beat), it hides the overlay and brings the native cursor back via `NativeCursorManager.SuspendForCoveredUi`, resuming when the pointer leaves. Full coverage above those bands would need a UIAccess build (signed, installed under Program Files).
- `RotationPreview.cs`: `RotationPreviewItem`, the Rotation submenu rows. Each animates a small cursor in the shortcut column, turning by the same rule the render loop uses for that `RotationMode`. Dropdown menus size and paint rows through the renderer, so the row reserves the column with figure spaces and `PhosphorMenuRenderer.OnRenderItemText` draws the stage; the clock runs only while the submenu is open.
- `ArkEmblem.cs`, `ArkEmblemGeometry.cs`: the ArkMark from the approved path geometry (generated by `tools/gen_emblem_geometry.py` from `packages/ui/src/brand`: the cube emblem and the aperture favicon; rerun it, never hand-edit). The tray icon is the untiled aperture favicon (cream A, green globe at full opacity so it reads at 16px, no background), fitted edge to edge to its own bounds because the dropped tile's padding only shrinks it. The app icon (exe, desktop and Startup shortcuts, taskbar, Alt+Tab) is `assets/omniwand.ico`, built by `tools/gen_app_icon.py` from the brand files with the tile kept (favicon-16 at 16, favicon-32 at 20 to 32, the aperture emblem tile at 40 to 256); `WidgetChrome.Attach` sets it on every widget window. Rerun the script when the brand marks change.
- `ModelPicker.cs`, `WidgetDrag.cs`, `PhosphorToast.cs`, `PhosphorMenuRenderer.cs`, `PhosphorTheme.cs`: shared Phosphor UI.
- `VrStreamDetector.cs`: Air Link / Virtual Desktop detection.

## Rules

1. Use the most recent Relic Phosphor Shell. Pull colors, radii, spacing and type sizes from `PhosphorTheme`; do not add hex values or px literals for tokenized values in widget code. `packages/tokens` and `packages/ui` in `E:\ArkStation\.ark` are the only design source of truth (Ark rule 13): change a value there (proposed and approved), regenerate `PhosphorTokens.cs`, and never add a parallel theme. Resolve design questions through `GET /api/veritas/design-systems?scope=<scope>` before inventing visuals.
2. Terminology is GrimX and Flow (Spell, Ritual, Symphony, Ultima, Charm, Summon). Never Ev3-Orb or Omnidex.
3. Isolated work only: branch `feat/<slug>` or `fix/<slug>` from `origin/main` in a SolaTree worktree. Keep unrelated dirty files untouched.
4. Markdown is intent, code is state. Verify behavior in code and a running process before claiming it works.
5. The native Logi Options+ Actions Ring is the primary MX Master 4 path (operator ruling 2026-10-15). The Logi plugin is universal (`HasNoApplication => true`) so its slot actions are assignable in every application; the F15 orb overlay stays as the keyboard fallback only.
6. Widgets compose `PhosphorKit` primitives: eyebrows are JetBrains Mono 10px, 0.16em tracking, with `//` separators (`PhosphorTheme.Locals`), buttons are 44px uppercase with one primary per region, badges are mono outlines, fields are bordered hosts. Fonts load privately from `distonts` (copied from `packages/tokens/assets/fonts` by the csproj). Inter is not installed on gala, so UI text falls back to Segoe UI until it is.
7. The ArkMark is drawn from `ArkEmblemGeometry.cs`; never redraw it by hand. The old hexagon and the `omniwand.ico` "A" mark are not canon.
8. Logi icons come from the design system only. `logi-mx4-plugin/icons/build_icons.py` holds the glyphs, copied from the Agent UI Kit Icons artboard and the Ark Animated Icons zone set (24 viewBox, 1.8 stroke, round caps), maps each command class to one, and writes `icons/*.svg` (embedded, drawn in emblem cream on the matte ground tiles via `BitmapImage.FromSvg`) plus `actionicons/` and `actionsymbols/` for Options+: a matte black disc (`#050607`) with the glyph outlined in cream (`#E4D9C0`). Options+ shows symbol SVGs in their authored colors but draws its own light bubble around them (even in its dark mode), so the disc sits inside a grey rim; that bubble is not ours to change. Change an icon there and rerun it; never draw badge text or ad hoc glyphs.
9. GrimX Flow slots 1 to 6 cast through Input Spine and report in a toast; they never open Wiz (slot 7 is Wiz). A cast is reported as cast only when Spine answers `matched: true`.
10. Notifications are `PhosphorToast.Show(title, body, eyebrow, ms, tone)`: a PhosphorKit panel with a rounded window region, a tracked mono eyebrow using `//` (never a middle dot), a sentence-case title, and a state edge from `ToastTone`: Info grey, Success moss, Warning ember (not cast, pending), Error rust. Never a Windows balloon.

## Build and run

Always disable build servers (paging file pressure on this machine):

```powershell
Get-Process Omniwand -ErrorAction SilentlyContinue | Stop-Process -Force
dotnet publish E:\ArkStation\augments\omniwand\Omniwand.csproj -c Release -o E:\ArkStation\augments\omniwand\dist --disable-build-servers -p:UseSharedCompilation=false -nologo
Invoke-CimMethod -ClassName Win32_Process -MethodName Create -Arguments @{ CommandLine='"E:\ArkStation\augments\omniwand\dist\Omniwand.exe"'; CurrentDirectory='E:\ArkStation\augments\omniwand\dist' }
```

- Input Studio's runtime task (`E:\ArkStation\runtimes\input-studio\start-omniwand-runtime.ps1`, scheduled task "Ark Omniwand Runtime") and the Logi plugin both relaunch `dist\Omniwand.exe` the moment no process exists, which locks `dist` mid-publish. Publish to `obj\stage` first, then stop Omniwand, `robocopy obj\stage dist /E`, and launch:

```powershell
dotnet publish E:\ArkStation\augments\omniwand\Omniwand.csproj -c Release -o E:\ArkStation\augments\omniwand\obj\stage --disable-build-servers -p:UseSharedCompilation=false -nologo
Get-Process Omniwand -ErrorAction SilentlyContinue | Stop-Process -Force; robocopy E:\ArkStation\augments\omniwand\obj\stage E:\ArkStation\augments\omniwand\dist /E
```

- A crash at startup shows as a `.NET Runtime` 1026 event in the Application log; read it before blaming the watchdog.
- Do not leave `dotnet run` in the background; launch the compiled exe.
- Launch through `Win32_Process.Create` so the app is not killed with the shell's job object.
- Omniwand hides every system cursor. If it crashes, restore with: `rundll32 user32.dll,UpdatePerUserSystemParameters`, or run `SystemParametersInfo(SPI_SETCURSORS)`. Exit via tray (`Ctrl+Alt+Q`) restores automatically.

Logi plugin:

```powershell
dotnet build E:\ArkStation\augments\omniwand\logi-mx4-plugin\ArkStationOmniwandPlugin.csproj -c Release -o E:\ArkStation\augments\omniwand\logi-mx4-plugin\bin\win --disable-build-servers -p:UseSharedCompilation=false -nologo
```

Copy `metadata\`, `events\` and `win\` into `%LOCALAPPDATA%\Logi\LogiPluginService\Plugins\ArkStationOmniwand` and zip the same layout to `dist\ArkStationOmniwand.lplug4` (plus `actionicons\` and `actionsymbols\`; no `bin\` duplicate, no `profiles\`). `LogiPluginTool.exe` is not directly runnable here, so the zip is built by hand. Restart `LogiPluginService.exe` after a copy and read `%LOCALAPPDATA%\Logi\LogiPluginService\Logs\plugin_logs\ArkStationOmniwand.log`: a clean load prints `13 dynamic actions loaded`. A second "already loaded" line a minute later hits every plugin and is Options+ reconnecting, not a fault. Haptic events are declared once in `events\DefaultEventSource.yaml`; do not re-add them in `Load()`. Omnitek classifies the plugin as Augment > Extension > desktop-extension (host Logi Options+), see `INVENTORY.json`.

Control pipe commands (`ArkStation.Omniwand.Control`, one line each): `orb:toggle`, `ghost:toggle`, `hud:summon`, `wiz:summon`, `ainbox:summon`, `hud:close`, `wiz:close`, `ainbox:close`, `widgets:close`, `slot:<id|1-8>`, `profile:cycle`, `scale:<delta>`.

## Tray menu and rounded windows

Tray rows are short sentence-case labels. Secondary detail goes in the dim mono right column (`ShortcutKeyDisplayString`, e.g. orb slots `1 // CAST`, cursor sizes `1.25x`) and longer descriptions in `ToolTipText`. Submenus run at text-size-data (12px) so they stay narrow; the top menu keeps text-size-body. Section headers inside a submenu are `PhosphorMenuEyebrow` rows, never disabled items. Hover follows the Highlight Aura Rule (`PhosphorTheme.DrawHighlightAura`): a coral leading-edge side light that fades out by about 60% of the row, rust for `DangerTag` rows, and the same aura on a parent row while its submenu is open. Never a grey fill, outline or pill.

A UI Lab for tuning every surface against the tokens is planned as a 4GE extension, not inside Omniwand.

Rounded windows are clipped with a window region (`WidgetChrome.ClipToFrame`, `PhosphorPaint.ClipRounded`) so no square corners or light ears show; fields, selects and the SpecCard paint their own rounded fill on a transparent background for the same reason. `DrawToBitmap` ignores window regions, so check regions in code, not only in offscreen images.

## Air Link bare-desktop cursor (resolved)

Root cause (`OculusDash.exe`):
1. `OculusDash.exe`'s `ReactSystem` singleton (`RVA 0x1d86780`, offset `+0x218`) caches `HCURSOR -> CursorTexture` in a red-black tree `std::map` (`0x1640b0`) and never invalidates entries when Windows `SetSystemCursor` updates a system cursor slot in-place (since `SetSystemCursor` preserves the stock `HCURSOR` handle integer `65539` for `OCR_NORMAL`). If `OculusDash.exe` saw `65539` before Omniwand hid the cursors, it permanently served the cached white arrow texture.
2. `OculusDash.exe`'s monochrome cursor decoder (`0x169fe0`, used when `ICONINFO.hbmColor == 0`) fills transparent mask pixels (`AND=1, XOR=0`) with `RGB=(255,255,255), A=0`, whereas its color cursor path (`0x164204`, used when `hbmColor != 0` via `Bitmap(32,32,Format32bppArgb).GetHicon()`, `hotspot=(16,16)`) produces `RGBA=(0,0,0,0)`.

Fix implemented in `VrStreamDetector.cs` and `Program.cs`:
- `NativeCursorManager.HideSystemCursors()` defaults to `ArrowSlotStyle.ArgbClear` (`32x32` ARGB `alpha=0` via `GetHicon()`, `hotspot=(16,16)`) across all 20 system cursor slots.
- `VrStreamDetector.EnsureOculusDashCursorCacheClean()` inspects `OculusDash.exe`'s live `std::map` at `[ReactSystem + 0x218]` and resets the red-black tree head whenever any cached system cursor node lacks `hot=(16,16)` or `hbmColor != 0`.
- `CursorOverlayWindow.PulseCursorHandleForVr()` briefly clears `WS_EX_TRANSPARENT` for 80ms while answering `WM_SETCURSOR` with `IDC_HAND` (`65567`), forcing `OculusDash`'s desktop panel (`[panel + 0x128]`) to transition `65539 -> 65567 -> 65539` and immediately bind the transparent `65539` texture.

## Runtime, Startup & Logi Options+ Binding

- **Input Studio Runtime Supervisor (`:8842`)**: `apps/input-studio/server.ts` (`ensureOmniwandDesktopRuntime` + `/api/omniwand/status` + `/api/omniwand/start`) automatically starts and supervises `E:\ArkStation\augments\omniwand\dist\Omniwand.exe` whenever Input Studio starts and checks every 15s.
- **Ark Startup & Scheduled Task**:
  - `E:\ArkStation\runtimes\input-studio\start-omniwand-runtime.ps1` (`-Status`, `-Stop`, or default start) launches both Input Studio (`:8842`) and `Omniwand.exe`.
  - Registered under Windows Task Scheduler as `\Ark\Ark Omniwand Runtime` (`AtLogOn`) and wired into `start-arkstation.ps1`.
  - Shortcuts created at `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\Omniwand.lnk` and `Desktop\Omniwand.lnk` with `dist\omniwand.ico`.
- **Logi Options+ (`LogiPluginService`) & MX Master 4**:
  - `ArkStationOmniwand` (`0.2.0.1014`) is deployed to `%LOCALAPPDATA%\Logi\LogiPluginService\Plugins\ArkStationOmniwand` (with `metadata\LoupedeckPackage.yaml`, `events\DefaultEventSource.yaml`, and `bin\win\ArkStationOmniwandPlugin.dll`) and packed to `dist\ArkStationOmniwand.lplug4`.
  - Verified in `%LOCALAPPDATA%\Logi\LogiPluginService\Logs\plugin_logs\ArkStationOmniwand.log`: all 7 dynamic actions (`GrimXFlowOrbSlotsCommand`, `SummonGrimXFlowOrbCommand`, `ToggleGhostTrailerCommand`, `SummonWizCraftingCommand`, `SummonAInboxIntakeCommand`, `SummonOmniwandHudCommand`, `OmniwandThumbwheelScaleAdjustment`) and 5 MX Master 4 Haptic events are loaded by `LogiPluginService`.
  - Communicates over Named Pipe `\\.\pipe\ArkStation.Omniwand.Control` (concurrent per-client handler in `Program.cs`) and/or direct MX Master 4 `F15` (GrimX Flow Orb) and `F16` (GhostTrailer) low-level hooks.
